エンティティ管理

Person（個人）／ Corporation（企業）／ Organization（組織）の 3 種類のエンティティを、独立した 3 テーブルで管理します。各タブで全フィールドを個別に登録・編集・削除できます。

本プラグインの管理画面は admin.php?page=kapm に配置され、上部のナビゲーションタブで 3 つのエンティティ種別を切り替えます。デフォルトは Person タブで、URL クエリ &tab=corporation / &tab=organization で切り替わります。エンティティはすべて独立したカスタムテーブルに保存され、WordPress ユーザーとは関連付きません。

管理画面の共通操作

1

WordPress 管理画面の左サイドバーから 「Kashiwazaki SEO Author Panel Manager」（dashicons-id-alt アイコン）をクリックします。

2

上部の Person / Corporation / Organization タブをクリックして、管理したいエンティティ種別を選択します。

3

一覧画面の 「新規追加」 ボタンから登録画面を開き、各フィールドを入力して保存します。既存エンティティは 「編集」 リンクから修正できます。

4

削除は一覧の 「削除」 リンクから行います。削除操作には JavaScript の confirm() ダイアログが表示され、さらにサーバー側で nonce 検証が行われます。

保存先テーブル

3 種のエンティティは別テーブルに保存されます（{prefix}apm_persons / {prefix}apm_corporations / {prefix}apm_organizations）。テーブルはプラグイン有効化時に dbDelta() で作成され、インデックスは PRIMARY KEY (id) のみです。詳細な DB スキーマは トラブルシューティングの DB スキーマ表を参照してください。

Person（個人）タブ

Person タブは、記事の執筆者・レビュアー・編集者など「個人」を登録するためのタブです。ここで登録したエンティティはブロックエディタや [author_panel] ショートコードから Person の ID で参照され、Schema.org の Person 型 JSON-LD として出力されます。

Person 編集画面。下部に「パネルのデザイン」「パネルのカラー」があり、カラーを「カスタム」にすると背景色・文字色・アクセント色のカラーピッカーが表示されます

Corporation（企業）タブ

Corporation タブは、記事の発行元や運営会社などの企業法人を登録するタブです。ここで登録したエンティティは Schema.org の Corporation 型として JSON-LD 出力されます。Corporation は Organization のサブタイプで、営利法人であることをより明示できます。

Corporation の基本フィールド（12 項目）

Organization（組織）タブ

Organization タブは、研究機関・業界団体・非営利組織・運営メディアなど、Corporation 以外の組織を登録するためのタブです。Schema.org の Organization 型として JSON-LD 出力されます。

Organization の基本フィールド（12 項目）

Organization のフォーム（admin/views/organization-form.php）のカラム構成は Corporation と完全に同一ですが、独立した DB テーブル {prefix}apm_organizations に保存され、Schema.org の型も異なります。Corporation と混在させず、営利法人以外は必ず Organization タブで登録してください。

Corporation と Organization の使い分け

一般的な営利企業（株式会社・合同会社等）は Corporation、学会・研究所・NPO・業界団体・運営メディア（ブランド名）などは Organization に登録してください。両者はテーブルも @id の接頭辞（#corporation-{id} / #organization-{id}）も分かれており、JSON-LD 上では別エンティティとして扱われます。

住所・連絡先・法人情報（Corporation / Organization 共通）

Corporation と Organization の編集画面には、基本の項目の下に「住所・電話番号」「メール・問い合わせ窓口」「法人情報」の 3 つのまとまりがあります（v1.0.4 で追加）。どれも任意で、空欄の項目は出力しません。入力した項目はすべて構造化データ（JSON-LD）に出力します。パネルでは、住所と電話番号を説明文の下に表示し、入力した項目の一覧を名前の横の i ボタンの吹き出しに表示します。Person にはこの項目はありません。

出力のきまり

  • 住所（address）は、郵便番号・都道府県・市区町村・番地・建物名のどれか 1 つでも入っているときだけ出力します。国コードだけでは出力しません（国コードには既定で JP が入るため）。
  • 問い合わせ窓口（contactPoint）は、窓口の電話番号かメールアドレスがあるときだけ出力します。窓口の種類だけでは出力しません。
  • 従業員数は、人数なら value、範囲なら minValue / maxValue で出力します。
  • 書式が決まっている項目（国コード・メールアドレス・設立日・従業員数）に合わない値を入れて保存すると、その項目は空欄で保存され、画面上部に「「〇〇」は書式が正しくないため、空欄として保存しました。」と表示されます。国コード・メールアドレス・設立日は、保存する前にブラウザも書式を確認します。

パネルでの表示

住所と電話番号は説明文の下に表示され、名前の横に i ボタンが付きます

住所は、地図ピンのアイコン付きで 1 行にまとめて表示します。国コードが JP か空欄なら「〒郵便番号 都道府県市区町村番地・建物名」、それ以外の国なら「番地, 市区町村, 州 郵便番号」の順です。電話番号は受話器のアイコン付きで、入力したとおりの文字で表示し、タップすると電話をかけられるリンク（tel:）にします。アイコンには読み上げ用の名前（「住所」「電話番号」）が付いています。

名前の横の吹き出し（i ボタン）

i ボタンにマウスを乗せると、入力した項目の一覧が吹き出しで出ます

住所・連絡先・法人情報のどれかが入力されていると、名前の横に i ボタン（dashicons-info-outline）が付きます。ボタンにマウスを乗せるか、タップするか、キーボードで移動すると、入力した項目の「項目名」と「内容」の一覧が吹き出しで出ます。国コードしか入っていない場合（既定の JP だけの場合）は、ボタンは出ません。

  • 並びは入力画面と同じです。住所は 1 行にまとめ、設立日は「2012年6月26日」、従業員数は「50人」「100〜999人」の形で表示します。国コードは住所の書き方の切り替えにだけ使い、一覧には出しません。
  • 吹き出しは、名前の行のすぐ下に、パネルの情報欄（名前・説明文の列）の幅いっぱいで出します。i ボタンの位置に合わせないので、名前が長くても画面からはみ出しません。画面幅が 600px 以下のときは、項目名と内容を縦に並べます。
  • 吹き出しは role="tooltip" で、ボタンから aria-describedby で参照しています。Esc キーで閉じられます。この Esc の処理だけは小さなスクリプト（ハンドル kapm-panel-info、フッターにインライン出力）で行い、吹き出しのあるパネルを出したページにだけ読み込みます。表示自体は CSS だけで行います。

Google のドキュメントとの対応

項目と書式は、Google 検索セントラルの Organization の構造化データに合わせています。同ページによると必須の項目はなく、当てはまる項目をできるだけ入れることが勧められています。また、組織の情報はホームページか組織を説明する 1 ページに置くことを勧めており、すべてのページに入れる必要はないとしています。ネットショップ向けの返品・配送・会員プログラム（hasMerchantReturnPolicy など）は、このプラグインの対象外です。

Role から Schema.org プロパティへの変換（role_to_property）

Custom モード（他プラグインの既存スキーマに著者情報を紐付ける出力方式）では、各エンティティの role フィールド値が class-shortcode.php の role_to_property() メソッドで Schema.org のプロパティ名に変換され、対象ノードに付与されます。対応表は以下のとおりです（大文字小文字は区別されません）。

入力 role 値（小文字化後） 出力プロパティ名
author / writerauthor
publisherpublisher
editoreditor
reviewerreviewedBy
contributorcontributor
creatorcreator
sponsor / fundersponsor
translatortranslator
上記以外（未定義値・空文字）author（フォールバック）
Standard モードでは role は参照されません

Standard モード（ページ本文の直後に独立 JSON-LD を出力する方式）では、@graph に Person / Corporation / Organization ノードを並べるだけで、Article 等への紐付けは行いません。そのため role_to_property() はショートコードの mode="custom" 時にのみ使われます。

パネルのデザインとカラー

各エンティティの HTML パネルの見た目は、「パネルのデザイン」（形）と「パネルのカラー」（色）の 2 項目で決まります。v1.0.2 までは 1 つの「パネルデザイン」に形と色（Dark）が混在していましたが、v1.0.3 で 2 項目に分けました。形と色を別々に選べるため、たとえば「カードの形でダーク」のような組み合わせも選べます。CSS は public/css/panel-style.css に定義されており、表示に JavaScript は使用しません。

デザインとカラーの組み合わせ見本（上から 標準・アクセント・ミニマル・カード × おまかせ、標準 × ダーク、カード × ブルー、アクセント × グリーン、アクセント × オレンジ、カード × カスタム）

カスタムカラーの指定

「パネルのカラー」で カスタム（色を指定） を選ぶと、その下に 背景色・文字色・アクセント色 の 3 つのカラーピッカーが表示されます（ほかのカラーを選んでいる間は非表示）。指定した色は、カードの style 属性に CSS 変数（--kapm-bg / --kapm-text / --kapm-name / --kapm-accent）として出力されます。

  • 背景色：パネルの背景
  • 文字色：名前・肩書き・紹介文などの文字。名前の色にも使われます
  • アクセント色：アクセント（左の太線）やカードのラベル、SNS アイコンにマウスを重ねたときの色

空のままにした色は既定値（背景 #ffffff・文字 #333333・アクセント #0073aa）になります。文字が読みにくくならないよう、背景色と文字色の明るさに十分な差をつけてください。

v1.0.2 までの「Dark」を使っていた場合

以前の保存値 panel_style = dark は、v1.0.3 では デザイン＝標準・カラー＝ダーク として読み替えて表示されます（データの書き換えは不要）。編集画面を開くと、この組み合わせが選ばれた状態で表示されます。以前の Dark にあった左の太線が必要な場合は、デザインを「アクセント（左に太線）」に変えてください。

エンティティごとに個別設定

デザインとカラーは エンティティごとに保存されます。同じ記事に Person と Corporation を並べて、それぞれ異なるデザイン・カラーを適用することもできます。画像の形（丸・四角・楕円など）は記事ごとにブロックで選びます（ショートコード＆ブロック参照）。

使用中の記事の確認

Person / Corporation / Organization の 編集画面下部に「使用中の記事」セクションが表示されます。そのエンティティを参照している投稿を自動検出して一覧表示する機能で、削除前の影響範囲確認に使えます。

実装は KAPM_Database::get_posts_using_entity() にあり、2 段階で記事を絞り込みます。

1

SQL LIKE で候補を抽出：wp_posts.post_content に "persons":" / "corporations":" / "organizations":" の文字列パターンを含む行を LIKE 検索します。post_status = 'publish' に限定されるため、下書き・非公開・予約投稿・ゴミ箱は検出されません。

2

parse_blocks() で再帰的に照合：候補記事ごとに parse_blocks() を実行し、block_tree_contains_entity() が innerBlocks を再帰的に辿ります。Group / Columns / Row / Reusable など ネストされたコンテナブロック内に配置された kapm/author-panel も検出対象です（v1.0.1 で追加）。

検出対象の制限

この逆引きは Gutenberg ブロック経由の参照のみを対象とします。ショートコード [author_panel persons="..."] で参照している場合、ブロック属性の JSON 形式とはパターンが一致しないため 検出されません。また、公開済み（publish）以外の投稿ステータスも対象外です。ネストブロック（Group / Columns 等）内の著者パネルは v1.0.1 以降で検出されます。

削除前の確認

エンティティを削除する前に、必ず「使用中の記事」セクションを確認してください。削除された ID を参照しているブロックはフロント側で「表示するエンティティ無し」として空出力になります（エラー表示ではなく、パネル自体が消える）。

保存・削除処理のセキュリティ

3 つのエンティティすべてに対して、保存と削除のたびに nonce 検証と capability チェックが行われます。具体的なアクション名は以下のとおりです。

操作 nonce アクション名 nonce フィールド名
Person 保存kapm_save_personkapm_person_nonce
Person 削除kapm_delete_personURL の _wpnonce
Corporation 保存kapm_save_corporationkapm_corporation_nonce
Corporation 削除kapm_delete_corporationURL の _wpnonce
Organization 保存kapm_save_organizationkapm_organization_nonce
Organization 削除kapm_delete_organizationURL の _wpnonce
管理画面全体の権限

管理画面の表示と保存・削除は current_user_can('manage_options')（管理者権限）でガードされています。REST API は編集者以上（edit_posts）で参照可能です。詳細は トラブルシューティングの REST API 仕様を参照してください。

アンインストール時のデータ削除

プラグイン削除で 3 テーブルが完全削除されます

WordPress 管理画面でプラグインを 削除すると、uninstall.php が実行され {prefix}apm_persons / {prefix}apm_corporations / {prefix}apm_organizations の 3 テーブルが DROP TABLE IF EXISTS により完全に消去され、テーブル構造のバージョンを記録するオプション kapm_db_version も削除されます。無効化（deactivate）では削除されませんが、削除（delete）は復元不可です。エンティティデータを保全する場合は事前に wp db export 等で必ずバックアップを取ってください。
